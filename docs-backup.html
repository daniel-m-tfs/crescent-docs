🌙 Crescent Framework

Framework web moderno e performático construído em Lua, Luvit e MySQL.

🚀 Comece Agora!

Baixe o Crescent Starter e comece a desenvolver em minutos:

📦 Download crescent-starter.zip

O que é Crescent?

Crescent é um framework web completo que combina a performance do Lua/LuaJIT com uma arquitetura moderna e modular inspirada em frameworks como NestJS e Laravel. Foi projetado para criar APIs REST e aplicações web de alto desempenho com código limpo e organizado.

✨ Principais Características

  • Performance Excepcional: LuaJIT oferece velocidade comparável a C
  • Arquitetura Modular: Controllers, Services, Models separados
  • ORM ActiveRecord: Trabalhe com banco de dados de forma intuitiva
  • CLI Poderoso: Gerador de código estilo Laravel Artisan
  • Middlewares Prontos: Auth, CORS, Security, Logger
  • Sistema de Migrations: Controle de versão do banco

📦 Instalação

1. Baixe o Crescent Starter

# Download via curl
curl -L https://github.com/daniel-m-tfs/crescent-framework/releases/download/Versões/crescent-starter.zip -o crescent-starter.zip

# Ou baixe diretamente pelo navegador:
# https://github.com/daniel-m-tfs/crescent-framework/releases

2. Descompacte e Acesse a Pasta

unzip crescent-starter.zip
cd crescent-starter

3. Instale as Dependências (se necessário)

# Script automatizado que instala tudo
./install-dependencies.sh

O script instalará (se necessário):

  • Luvit: Runtime Lua assíncrono
  • LuaRocks: Gerenciador de pacotes
  • MySQL + luasql-mysql: Banco de dados (opcional)
  • Dependências Lua: Bibliotecas adicionais (opcional)
💡 Dica: O script é interativo e pergunta antes de instalar cada componente. Se você já tem Luvit e LuaRocks instalados, ele apenas verificará e continuará.

4. Inicie o Servidor

luvit app.lua
# Servidor rodando em http://localhost:8080

5. Configure o Ambiente (Opcional)

cp .env.example .env
nano .env  # Configure MySQL, porta, etc.

🛣️ Rotas

O sistema de rotas do Crescent é simples e poderoso, permitindo definir endpoints HTTP facilmente.

Definindo Rotas

-- src/users/routes/user.lua
local UserController = require("src.users.controllers.user")

return function(app)
    -- GET /users
    app:get("/users", UserController.index)
    
    -- GET /users/:id
    app:get("/users/:id", UserController.show)
    
    -- POST /users
    app:post("/users", UserController.create)
    
    -- PUT /users/:id
    app:put("/users/:id", UserController.update)
    
    -- DELETE /users/:id
    app:delete("/users/:id", UserController.delete)
end

Parâmetros de Rota

-- Acesse parâmetros via ctx.params
function UserController.show(ctx)
    local id = ctx.params.id
    -- ...
end

Query Strings

-- GET /users?active=true&limit=10
function UserController.index(ctx)
    local active = ctx.query.active
    local limit = ctx.query.limit
    -- ...
end

Middleware em Rotas

local auth = require("crescent.middleware.auth")

return function(app)
    -- Rota protegida
    app:get("/admin", auth.verify, AdminController.index)
end

🎮 Controllers

Controllers são responsáveis por receber requisições HTTP e retornar respostas. Eles orquestram a lógica de negócio através dos Services.

Criando um Controller

luvit crescent-cli.lua make:controller User

Estrutura de um Controller

-- src/users/controllers/user.lua
local UserService = require("src.users.services.user")

local UserController = {}

-- GET /users
function UserController.index(ctx)
    local users = UserService.findAll()
    return ctx.json({ users = users })
end

-- GET /users/:id
function UserController.show(ctx)
    local id = ctx.params.id
    local user = UserService.findById(id)
    
    if not user then
        return ctx.status(404).json({ error = "Usuário não encontrado" })
    end
    
    return ctx.json({ user = user })
end

-- POST /users
function UserController.create(ctx)
    local data = ctx.body
    local user, err = UserService.create(data)
    
    if err then
        return ctx.status(400).json({ error = err })
    end
    
    return ctx.status(201).json({ user = user })
end

-- PUT /users/:id
function UserController.update(ctx)
    local id = ctx.params.id
    local data = ctx.body
    
    local user, err = UserService.update(id, data)
    
    if err then
        return ctx.status(400).json({ error = err })
    end
    
    return ctx.json({ user = user })
end

-- DELETE /users/:id
function UserController.delete(ctx)
    local id = ctx.params.id
    local success = UserService.delete(id)
    
    if not success then
        return ctx.status(404).json({ error = "Usuário não encontrado" })
    end
    
    return ctx.status(204).send()
end

return UserController

Métodos de Resposta

-- JSON response
ctx.json({ data = "valor" })

-- Status code
ctx.status(404)

-- Text response
ctx.send("Hello World")

-- Headers
ctx.header("Content-Type", "application/json")

-- Redirect
ctx.redirect("/login")

⚙️ Services

Services contêm a lógica de negócio da aplicação. Eles são responsáveis por processar dados, validar regras e interagir com Models.

Criando um Service

luvit crescent-cli.lua make:service User

Estrutura de um Service

-- src/users/services/user.lua
local User = require("src.users.models.user")

local UserService = {}

function UserService.findAll()
    return User:all()
end

function UserService.findById(id)
    return User:find(id)
end

function UserService.create(data)
    -- Validação de negócio
    if not data.email or data.email == "" then
        return nil, "Email é obrigatório"
    end
    
    -- Verifica se email já existe
    local existing = User:where("email", data.email):first()
    if existing then
        return nil, "Email já cadastrado"
    end
    
    -- Cria usuário
    local user = User:create(data)
    return user
end

function UserService.update(id, data)
    local user = User:find(id)
    if not user then
        return nil, "Usuário não encontrado"
    end
    
    user:update(data)
    return user
end

function UserService.delete(id)
    local user = User:find(id)
    if not user then
        return false
    end
    
    user:delete()
    return true
end

return UserService
💡 Melhor Prática: Mantenha Controllers magros e Services gordos. A lógica de negócio deve estar nos Services, não nos Controllers.

💾 Models

Models representam as entidades do banco de dados e herdam do ORM ActiveRecord.

Criando um Model

luvit crescent-cli.lua make:model User

Estrutura de um Model

-- src/users/models/user.lua
local Model = require("crescent.database.model")

local User = Model:extend({
    table = "users",
    
    -- Campos que podem ser preenchidos em massa
    fillable = {
        "name",
        "email",
        "password"
    },
    
    -- Campos ocultos (não aparecem em toTable())
    hidden = {
        "password"
    },
    
    -- Validações
    validations = {
        name = { "required", "min_length:3" },
        email = { "required", "email", "unique:users,email" },
        password = { "required", "min_length:6" }
    },
    
    -- Timestamps automáticos
    timestamps = true
})

return User

🗄️ ORM ActiveRecord

O Crescent inclui um ORM ActiveRecord completo inspirado no Laravel Eloquent.

Operações Básicas

-- Buscar todos
local users = User:all()

-- Buscar por ID
local user = User:find(1)

-- Criar
local user = User:create({
    name = "João",
    email = "joao@example.com"
})

-- Atualizar
user:update({ name = "João Silva" })

-- Deletar
user:delete()

-- Salvar (insert ou update)
user.name = "Novo Nome"
user:save()

Query Builder

-- WHERE
User:where("active", true):all()

-- WHERE com operadores
User:where("age", ">", 18):all()

-- ORDER BY
User:orderBy("created_at", "desc"):all()

-- LIMIT
User:limit(10):all()

-- SELECT específico
User:select("id", "name", "email"):all()

-- Primeiro resultado
local user = User:where("email", "test@example.com"):first()

-- Contar
local count = User:where("active", true):count()

Timestamps Automáticos

-- Com timestamps = true, o ORM gerencia automaticamente:
-- created_at - definido no insert
-- updated_at - atualizado a cada save/update

✅ Validações

O ORM inclui sistema de validação integrado.

Validações Disponíveis

validations = {
    -- Campo obrigatório
    name = { "required" },
    
    -- Tamanho mínimo
    password = { "min_length:6" },
    
    -- Tamanho máximo
    bio = { "max_length:500" },
    
    -- Email válido
    email = { "email" },
    
    -- Valor único no banco
    email = { "unique:users,email" },
    
    -- Múltiplas validações
    name = { "required", "min_length:3", "max_length:100" }
}

Validação Manual

local user = User:new({ name = "A" })
local valid, errors = user:validate()

if not valid then
    for field, error in pairs(errors) do
        print(field .. ": " .. error)
    end
end

🔗 Relações

Defina relações entre models facilmente.

Has Many

-- User tem muitos Posts
local User = Model:extend({
    table = "users"
})

function User:posts()
    return self:hasMany(Post, "user_id")
end

-- Uso
local user = User:find(1)
local posts = user:posts()

Belongs To

-- Post pertence a um User
local Post = Model:extend({
    table = "posts"
})

function Post:user()
    return self:belongsTo(User, "user_id")
end

-- Uso
local post = Post:find(1)
local user = post:user()

Has One

-- User tem um Profile
function User:profile()
    return self:hasOne(Profile, "user_id")
end

🔄 Sistema de Migrations

Migrations são uma forma de versionar as mudanças no banco de dados.

Estrutura de uma Migration

-- migrations/20260106123456_create_products_table.lua
local Migration = {}

-- Método up: aplica a migration
function Migration:up()
    return [[
        CREATE TABLE IF NOT EXISTS products (
            id INT AUTO_INCREMENT PRIMARY KEY,
            name VARCHAR(255) NOT NULL,
            description TEXT,
            price DECIMAL(10,2) NOT NULL,
            stock INT DEFAULT 0,
            active BOOLEAN DEFAULT true,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
            updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
            INDEX idx_name (name),
            INDEX idx_active (active)
        ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
    ]]
end

-- Método down: desfaz a migration
function Migration:down()
    return [[
        DROP TABLE IF EXISTS products;
    ]]
end

return Migration

Padrões de Nome

  • create_xxx_table - Cria tabela xxx
  • add_column_to_xxx - Adiciona coluna na tabela xxx
  • drop_xxx_table - Remove tabela xxx
  • update_xxx_table - Modifica tabela xxx
💡 Dica: O CLI extrai automaticamente o nome da tabela do nome da migration!

🔌 Middleware

Middlewares são funções que processam requisições antes de chegarem aos controllers.

Middlewares Disponíveis

Logger

local logger = require("crescent.middleware.logger")
app:use(logger)

CORS

local cors = require("crescent.middleware.cors")
app:use(cors({
    origin = "*",
    methods = "GET,POST,PUT,DELETE",
    headers = "Content-Type,Authorization"
}))

Security

local security = require("crescent.middleware.security")
app:use(security)

Auth

local auth = require("crescent.middleware.auth")

-- Proteger rota específica
app:get("/admin", auth.verify, AdminController.index)

Criando Middleware Customizado

-- middleware/custom.lua
local function myMiddleware(ctx, next)
    -- Código antes do controller
    print("Antes da requisição")
    
    -- Chama próximo middleware/controller
    next()
    
    -- Código depois do controller
    print("Depois da requisição")
end

return myMiddleware

🌐 Configuração NGINX

Use NGINX como proxy reverso para produção.

Arquivo de Configuração

upstream crescent_app {
    server 127.0.0.1:8080;
}

server {
    listen 80;
    server_name seu-dominio.com;

    location / {
        proxy_pass http://crescent_app;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Instalando e Ativando

# Copiar configuração
sudo cp config/nginx.conf /etc/nginx/sites-available/crescent

# Criar link simbólico
sudo ln -s /etc/nginx/sites-available/crescent /etc/nginx/sites-enabled/

# Testar configuração
sudo nginx -t

# Recarregar NGINX
sudo systemctl reload nginx
⚠️ Atenção: Não esqueça de configurar SSL/TLS para produção usando Let's Encrypt ou similar.
